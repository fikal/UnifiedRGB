What it actually does

58 effects, on any device or any zone

Rainbows, meteors, plasma, aurora, candle flicker, rain, Matrix, starfield, police, heartbeat — plus audio-reactive bars and pulses on event-driven WASAPI capture that react the instant sound does. Add whole-screen ambient, Wallpaper Engine capture, and Razer Chroma game sync without Razer software installed.

Apply an effect to everything at once, to one device, or to a single fan ring. Every part animates independently.

Colors you actually chose

A real wheel with brightness, hex and RGB entry, and your own saved swatches. The Palette Library keeps curated presets and your own sets, and imports straight from a coolors.co URL or a pasted list of hex codes.

A dashboard on your pump LCD

Drag-and-drop designer for Thermalright 240×320 pump displays: CPU and GPU temps, clock faces, date, fan RPM, network throughput, weather, and free text — over your own image or GIF background, with multiple screens and a scene sequencer.

Fan curves that respect your other tools

Temperature-driven curves that follow the CPU, the GPU, or whichever is hotter — with live gauges, per-fan profiles, a drag-to-edit editor, and a thermal failsafe that hands control back to the BIOS if anything goes wrong.

Fans you leave on Auto are never touched, so your BIOS profiles and GPU tools keep working exactly as they did.

Fast is a feature

Under 5% of one core with the window open, near-silent in the tray, and almost zero allocation in steady state. Every driver de-duplicates frames at the write boundary so your USB bus isn't flooded with identical packets.

Profiles & hotkeys

Save setups and switch them with Ctrl+Alt+1…9 — hotkeys that work inside games. Per-app auto-switching, night mode with an idle gate, master brightness, and per-device disable.

Updates without the launcher

One click, straight from GitHub Releases, verified against the published SHA-256 before it swaps itself. Don't want the check? Turn it off and the app makes no network requests at all.

Where the others win

If one of these matters more to you than everything above, use the other tool — that's the honest answer, and you can run UnifiedRGB alongside most of them.

  • OpenRGB supports vastly more hardware and runs on Linux and macOS. If your gear isn't in our list, OpenRGB probably has it — which is exactly why UnifiedRGB bridges to it instead of pretending otherwise. Parts of our Gigabyte and Logitech drivers are ports of OpenRGB's GPLv2 code, and this project is GPLv2 because of it.
  • SignalRGB has a much larger device library, a huge catalogue of effects and community lightscripts, and more per-game integrations. Its multi-device "canvas" model — one effect painted across your whole desk as a single image — is genuinely slicker than anything here.
  • Artemis has the most powerful customisation engine of anything here — layers, conditions, and data bindings that drive lighting from live values, closer to a visual scripting environment than an effect picker. Nothing in UnifiedRGB approaches that depth.
  • Aurora owns per-game lighting. It reads real in-game state for specific titles rather than sampling the screen, which is a different and better thing when a game is supported.
  • Vendor apps, for all the bloat, remain the only way to get firmware updates, onboard-memory profiles that persist with no software running, macro engines, and device-specific settings like mouse DPI stages or keyboard actuation points. They also come with actual support staff.
  • UnifiedRGB is young. It went public in September 2026. The device list is short, the binary is unsigned, and the community is small. If you need something battle-tested across thousands of configurations today, it isn't this — yet.

What about JackNet RGB Sync?

It's gone — rgbsync.com now says plainly that "JackNet is retired," and its team went on to build SignalRGB. Worth knowing if you're still searching for it.

It's also a useful illustration of the difference in approach. JackNet synced your lighting by driving the vendor apps through their SDKs, so iCUE, Aura, Synapse, and the rest all had to stay installed and running underneath it. UnifiedRGB talks to the hardware itself — the vendor software isn't required, and in most cases shouldn't be running at all. That's more work per device, which is why the supported list is shorter, but it's also why there's nothing else left running on your machine.

Read this before you install

It needs administrator

Talking to hardware directly means kernel-level access. UnifiedRGB installs PawnIO, a signed, module-constrained kernel driver, for CPU temperatures, SMBus (DRAM lighting), and fan control. That's real access to your machine — understand it before you run it.

DRAM lighting talks raw SMBus

It follows OpenRGB's proven ENE detection and writes only to detected ENE controllers. As with every tool in this category: writing to the wrong SMBus device can permanently damage hardware.

The download is unsigned

A code-signing certificate costs money this project doesn't take, so SmartScreen will warn on first run — More info → Run anyway. Every release publishes a SHA-256 you can verify, and you can always build it yourself from source.

Questions people actually ask

Is it really free? What's the catch?

Free, and there's no paid tier to upsell you to. It's GPLv2 open source — the whole thing is on GitHub, including the reverse-engineered device protocols. The catch is the honest one: it supports far less hardware than the big tools, and it's maintained by one person.

Does it phone home?

One request: a check of this project's GitHub Releases at startup, so the app can offer you a new version. Switch it off in Settings and it makes no network requests at all. There is no telemetry, no analytics, and no account. The "Report a problem" button writes a diagnostic file to your Desktop and opens a pre-filled GitHub issue — nothing is uploaded without you posting it. This website has no trackers, no analytics, and loads nothing from third parties either.

Why is the download so large?

It bundles the entire .NET runtime, so there's nothing to install and no framework to keep in sync — one file that runs. That trades disk space for never fighting a runtime installer.

Can I run it next to iCUE, L-Connect, or OpenRGB?

Usually, but two programs writing the same device will fight over it — the lighting flickers between them. Best results come from letting UnifiedRGB own the devices it drives natively and closing the vendor app. Its OpenRGB bridge is managed automatically and never touches hardware UnifiedRGB already drives.

My device isn't supported. Now what?

Try the OpenRGB bridge first — it covers over a thousand devices and turns on with one checkbox. If that misses too, open a device request. Captures and protocol notes make a driver dramatically more likely.

Does it work on Linux?

No — it's a Windows app (WPF, .NET 10) and the kernel-access pieces are Windows-specific. On Linux, OpenRGB is the right answer.
